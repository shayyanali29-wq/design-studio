# Internationalization (i18n) Rules

## Overview

Design Studio supports **all languages and writing systems**. This document provides research-backed rules for creating interfaces that work globally.

---

## Core Principles

### 1. Logical CSS Properties (Not Physical)
Use logical properties instead of physical ones for proper RTL support.

**❌ Physical (breaks in RTL):**
```css
margin-left: 16px;
padding-right: 24px;
text-align: left;
border-left: 1px solid;
```

**✅ Logical (works in all directions):**
```css
margin-inline-start: 16px;
padding-inline-end: 24px;
text-align: start;
border-inline-start: 1px solid;
```

### 2. Mirrored Directional Icons
Icons that indicate direction must mirror in RTL.

**❌ Non-mirrored (confusing in RTL):**
```tsx
<ArrowRightIcon />
<ChevronRightIcon />
<ForwardIcon />
```

**✅ Mirrored (correct in all directions):**
```tsx
// Use logical properties or conditional rendering
<Icon className="rtl:rotate-180" />

// Or use directional-aware icons
<ArrowEndIcon /> // Points to end of line (right in LTR, left in RTL)
<ChevronEndIcon />
```

### 3. Intl-Formatted Numbers and Dates
Use the `Intl` API for proper formatting.

**❌ Manual formatting (locale-dependent):**
```tsx
const price = `$${amount.toFixed(2)}`;
const date = `${month}/${day}/${year}`;
```

**✅ Intl formatting (locale-aware):**
```tsx
const price = new Intl.NumberFormat(locale, {
  style: 'currency',
  currency: 'USD'
}).format(amount);

const date = new Intl.DateTimeFormat(locale, {
  year: 'numeric',
  month: 'long',
  day: 'numeric'
}).format(new Date());
```

### 4. Fonts That Cover Target Scripts
Ensure fonts support all required scripts.

**❌ Fonts that don't cover Arabic:**
```css
font-family: 'Geist Sans', system-ui, sans-serif;
/* Geist Sans doesn't support Arabic */
```

**✅ Fonts with Arabic support:**
```css
font-family: 'Geist Sans', 'Noto Sans Arabic', system-ui, sans-serif;
/* Falls back to Noto Sans Arabic for Arabic text */
```

### 5. Text Expansion Headroom
Account for text expansion in translations.

**Rule:** +30-40% text-expansion headroom for German, Finnish, Portuguese
**Rule:** +50-100% for some Asian languages

**❌ No headroom (text overflows):**
```tsx
<div className="w-48">
  <button className="truncate">Settings</button>
  {/* German: "Einstellungen" (50% longer) */}
</div>
```

**✅ With headroom (text fits):**
```tsx
<div className="w-64">
  <button className="truncate">Settings</button>
  {/* German: "Einstellungen" fits */}
</div>
```

## RTL (Right-to-Left) Support

### Languages That Use RTL
- Arabic (ar)
- Hebrew (he)
- Urdu (ur)
- Persian/Farsi (fa)
- Pashto (ps)
- Sindhi (sd)
- Uyghur (ug)
- Kurdish (ku)
- Divehi (dv)
- Yiddish (yi)

### RTL Implementation

#### 1. Set Document Direction
```tsx
// In your root layout
<html lang={locale} dir={isRTL ? 'rtl' : 'ltr'}>
```

#### 2. Use Logical Properties
```css
/* ❌ Physical */
.container {
  margin-left: 16px;
  padding-right: 24px;
  text-align: left;
  border-left: 1px solid #e5e7eb;
}

/* ✅ Logical */
.container {
  margin-inline-start: 16px;
  padding-inline-end: 24px;
  text-align: start;
  border-inline-start: 1px solid #e5e7eb;
}
```

#### 3. Tailwind Logical Properties
```tsx
// ❌ Physical (breaks in RTL)
<div className="ml-4 pr-6 text-left border-l" />

// ✅ Logical (works in all directions)
<div className="ms-4 pe-6 text-start border-s" />
```

**Tailwind v4 logical property classes:**
- `ms-*` / `me-*` → margin-inline-start/end
- `ps-*` / `pe-*` → padding-inline-start/end
- `start-*` / `end-*` → inset-inline-start/end
- `text-start` / `text-end` → text-align
- `border-s` / `border-e` → border-inline-start/end
- `rounded-s-*` / `rounded-e-*` → border-start/end radius
- `float-start` / `float-end` → float
- `clear-start` / `clear-end` → clear

#### 4. Flexbox and Grid
Flexbox and Grid automatically reverse in RTL when using `direction: rtl`.

```tsx
// This automatically reverses in RTL
<div className="flex items-center gap-4">
  <Icon />
  <span>Label</span>
</div>

// Icon will be on right in RTL, left in LTR
```

#### 5. Transform and Translate
Use logical transforms for RTL support.

```tsx
// ❌ Physical (breaks in RTL)
<div className="translate-x-4" />

// ✅ Logical (works in all directions)
<div className="translate-x-4 rtl:-translate-x-4" />

// Or use CSS logical properties
<div style={{ insetInlineStart: '16px' }} />
```

## CJK (Chinese, Japanese, Korean) Support

### Font Stacks
```css
/* Chinese (Simplified) */
font-family: 'Geist Sans', 'Noto Sans SC', system-ui, sans-serif;

/* Chinese (Traditional) */
font-family: 'Geist Sans', 'Noto Sans TC', system-ui, sans-serif;

/* Japanese */
font-family: 'Geist Sans', 'Noto Sans JP', system-ui, sans-serif;

/* Korean */
font-family: 'Geist Sans', 'Noto Sans KR', system-ui, sans-serif;
```

### Text Expansion
- Chinese: Minimal expansion
- Japanese: Minimal expansion
- Korean: Minimal expansion
- But: Line breaking rules differ

### Line Breaking
```css
/* Allow breaks anywhere for CJK */
.cjk-text {
  word-break: break-all;
  line-break: anywhere;
}

/* Or use strict rules */
.cjk-text-strict {
  word-break: keep-all;
  line-break: strict;
}
```

## Loading Fonts for Multiple Scripts

### Strategy 1: System Fonts First
```css
font-family: 
  'Geist Sans',           /* Primary Latin */
  'Noto Sans Arabic',     /* Arabic fallback */
  'Noto Sans Hebrew',     /* Hebrew fallback */
  'Noto Sans SC',         /* Chinese fallback */
  'Noto Sans JP',         /* Japanese fallback */
  'Noto Sans KR',         /* Korean fallback */
  system-ui,              /* System fallback */
  sans-serif;             /* Generic fallback */
```

### Strategy 2: Subset Loading
```tsx
// Load only needed subsets
import { GeistSans } from 'geist/font/sans';
import { NotoSansArabic } from 'next/font/google';

const geistSans = GeistSans({
  subsets: ['latin'],
  variable: '--font-geist-sans',
});

const notoArabic = NotoSansArabic({
  subsets: ['arabic'],
  variable: '--font-noto-arabic',
});
```

### Strategy 3: Conditional Loading
```tsx
// Load fonts based on locale
const getFontForLocale = (locale: string) => {
  switch (locale) {
    case 'ar':
      return 'Noto Sans Arabic';
    case 'he':
      return 'Noto Sans Hebrew';
    case 'ja':
      return 'Noto Sans JP';
    default:
      return 'Geist Sans';
  }
};
```

## Text Expansion Guidelines

### Expansion Rates by Language
| Language | Expansion Rate | Notes |
|----------|----------------|-------|
| English | Baseline | - |
| German | +30-40% | Long compound words |
| Finnish | +30-40% | Agglutinative language |
| Portuguese | +30-40% | Longer than Spanish |
| French | +15-20% | Slightly longer than English |
| Spanish | +15-20% | Slightly longer than English |
| Italian | +15-20% | Similar to Spanish |
| Arabic | +20-30% | Varies by context |
| Japanese | +10-20% | Depends on kanji usage |
| Chinese | -10-10% | Often shorter than English |
| Korean | +10-20% | Depends on context |

### Implementation
```tsx
// ❌ Fixed width (breaks with expansion)
<div className="w-48">
  <button>Settings</button>
</div>

// ✅ Flexible width (accommodates expansion)
<div className="min-w-[12rem] max-w-[16rem]">
  <button>Settings</button>
</div>

// ✅ Or use content-based sizing
<div className="w-fit">
  <button>Settings</button>
</div>
```

## Number and Date Formatting

### Numbers
```tsx
// Currency
new Intl.NumberFormat('de-DE', {
  style: 'currency',
  currency: 'EUR'
}).format(1234.56);
// → "1.234,56 €"

new Intl.NumberFormat('en-US', {
  style: 'currency',
  currency: 'USD'
}).format(1234.56);
// → "$1,234.56"

// Compact notation
new Intl.NumberFormat('en-US', {
  notation: 'compact',
  maximumFractionDigits: 1
}).format(1234567);
// → "1.2M"

// Percent
new Intl.NumberFormat('en-US', {
  style: 'percent',
  minimumFractionDigits: 1
}).format(0.856);
// → "85.6%"
```

### Dates
```tsx
// Full date
new Intl.DateTimeFormat('de-DE', {
  year: 'numeric',
  month: 'long',
  day: 'numeric'
}).format(new Date());
// → "6. August 2026"

// Short date
new Intl.DateTimeFormat('en-US', {
  month: 'short',
  day: 'numeric'
}).format(new Date());
// → "Aug 6"

// Relative time
new Intl.RelativeTimeFormat('en-US', {
  numeric: 'auto'
}).format(-2, 'day');
// → "2 days ago"
```

### Lists
```tsx
// List format
new Intl.ListFormat('en-US', {
  style: 'long',
  type: 'conjunction'
}).format(['Apples', 'Oranges', 'Bananas']);
// → "Apples, Oranges, and Bananas"
```

## Common Mistakes

### ❌ Don't: Use Physical Properties
```css
/* BAD: Breaks in RTL */
.container {
  margin-left: 16px;
  padding-right: 24px;
  text-align: left;
}
```

### ✅ Do: Use Logical Properties
```css
/* GOOD: Works in all directions */
.container {
  margin-inline-start: 16px;
  padding-inline-end: 24px;
  text-align: start;
}
```

### ❌ Don't: Hardcode Text Direction
```tsx
// BAD: Assumes LTR
<div className="text-left">
  <span>$1,234.56</span>
</div>
```

### ✅ Do: Use Logical Direction
```tsx
// GOOD: Works in all directions
<div className="text-start">
  <span>{formatCurrency(amount)}</span>
</div>
```

### ❌ Don't: Use Fonts Without Script Support
```css
/* BAD: Geist Sans doesn't support Arabic */
body {
  font-family: 'Geist Sans', sans-serif;
}
```

### ✅ Do: Include Script Fallbacks
```css
/* GOOD: Falls back to Arabic font */
body {
  font-family: 'Geist Sans', 'Noto Sans Arabic', sans-serif;
}
```

### ❌ Don't: Assume Fixed Text Length
```tsx
// BAD: Text overflows in German
<div className="w-32">
  <button>Settings</button>
  {/* German: "Einstellungen" overflows */}
</div>
```

### ✅ Do: Account for Text Expansion
```tsx
// GOOD: Flexible width
<div className="min-w-[8rem]">
  <button>Settings</button>
</div>
```

## Checklist

Before shipping, verify:

### RTL Support
- [ ] Document direction set based on locale
- [ ] All CSS uses logical properties
- [ ] Directional icons mirror in RTL
- [ ] Text alignment uses `start`/`end`
- [ ] Borders use `inline-start`/`inline-end`
- [ ] Margins/padding use logical properties
- [ ] Flexbox/Grid layouts work in RTL

### CJK Support
- [ ] Fonts support target scripts
- [ ] Line breaking rules appropriate
- [ ] Text expansion accommodated

### Number/Date Formatting
- [ ] Numbers use `Intl.NumberFormat`
- [ ] Dates use `Intl.DateTimeFormat`
- [ ] Currency uses locale-appropriate symbols
- [ ] Lists use `Intl.ListFormat`

### Font Loading
- [ ] Primary font covers Latin script
- [ ] Fallback fonts cover other scripts
- [ ] Fonts loaded efficiently (subsetting)
- [ ] Font-display: swap used

### Text Expansion
- [ ] +30-40% headroom for German/Finnish/Portuguese
- [ ] Flexible widths for buttons/labels
- [ ] No text truncation without ellipsis
- [ ] Test with longest expected translation

## Research Backing

### Why i18n Matters:
- **72%** of users prefer to buy from sites in their language (Source: Common Sense Advisory)
- **56%** of users say native-language information is more important than price (Source: CSA Research)
- **85%** of users won't buy from a site if the checkout isn't in their language (Source: CSA Research)

### Why RTL Matters:
- **400+ million** Arabic speakers worldwide
- **9+ million** Hebrew speakers
- **100+ million** Urdu speakers
- **80+ million** Persian speakers

### Why Proper Formatting Matters:
- **40%** of users abandon sites with poor localization (Source: Localization Industry Standards Association)
- **67%** of users expect customer support in their language (Source: Common Sense Advisory)

## Conclusion

i18n is not optional. It's a core requirement for global products. Use logical properties, support all scripts, format numbers and dates properly, and account for text expansion. The result: interfaces that work for everyone, everywhere.
