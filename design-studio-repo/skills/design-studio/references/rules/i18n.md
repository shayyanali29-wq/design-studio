# Rules: Internationalization & RTL (first-class, not an afterthought)

The moment the brief includes any locale beyond en-Latn, this file is P0.

## 1. Font coverage by script (pick from here, not from the Latin list)
| Script | Recommended families |
|---|---|
| Latin/extended | Geist, Inter, Outfit, Satoshi, Noto Sans |
| Arabic | IBM Plex Sans Arabic, Noto Sans Arabic (UI), Noto Naskh Arabic (editorial), Cairo, Tajawal |
| Urdu | Noto Nastaliq Urdu (display/editorial), Noto Sans Arabic + Noto Naskh for UI-cleaner reads; test Nastaliq line-height carefully |
| Persian | Vazirmatn, IRANSans-style, Noto Sans Arabic |
| Hebrew | Heebo, Rubik, Noto Sans Hebrew |
| Devanagari (Hindi etc.) | Mukta, Hind, Noto Sans Devanagari |
| Bengali, Tamil, Telugu, etc. | Noto Sans {Script} (guaranteed), system stacks |
| Chinese | Noto Sans SC/TC/HK, PingFang (iOS), Microsoft YaHei (Win) |
| Japanese | Noto Sans JP, Hiragino |
| Korean | Noto Sans KR |
| Cyrillic/Greek | Inter, Roboto, Noto Sans (full coverage) |
| Thai/Khmer/Lao | Noto Sans {Script}; NO letter-spacing ever |

P0: never ship a Latin-only font for these scripts. Test the actual glyphs, not the font name.

## 2. Script-specific typography
- Arabic/Urdu/Persian: NO letter-spacing (P0, breaks joining); line-height +10-25% vs Latin; baseline sits deeper. Nastaliq needs EXTRA line-height (1.9-2.3) and generous vertical padding; avoid Nastaliq below 16px.
- CJK: line-height 1.7-1.9; no italic (use weight or color for emphasis, italic is synthetic and ugly); no uppercase transforms; shorter measures.
- Indic scripts: watch vowel sign clipping at tight line-heights; +10-15% leading.

## 3. RTL layout (P0 for ar/he/ur/fa)
- Logical properties everywhere: `margin-inline-start` (not `margin-left`), `padding-inline-end`, `inset-inline-start`, `border-start`, `text-align: start`. Tailwind: `ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`.
- Set `dir="rtl"` at root for RTL pages; layout auto-flips when built on logical properties/flex/grid. Never hand-mirror with `left/right`.
- Mirror arrows/chevrons/back/forward icons and progress directions (`transform: scaleX(-1)` or logical icon variants). Never mirror: logos, clocks, media controls (play stays), brand marks, charts' data axes.
- Numbers stay left-to-right inside RTL text (use `dir="ltr"` spans or Unicode isolates for phone numbers, codes, mixed tokens).
- Mobile: swipe directions, back gestures, and tab order follow the mirrored layout.

## 4. Locale-aware formatting (P0)
- `Intl.NumberFormat(locale, {style:'currency', currency})`: never `"$" + price`. Urdu/Pakistan: `en-PK` or `ur-PK`, PKR formatting and grouping conventions differ by locale.
- `Intl.DateTimeFormat`: no hardcoded MM/DD/YYYY. Calendars: `gregory` default, support `islamic`/`persian` when audience needs.
- `Intl.PluralRules` / ICU MessageFormat for plurals: Arabic has 6 plural categories; English-style `count == 1 ? singular : plural` is wrong (P1).
- Name order, address order, phone formats are locale-defined (see commerce checkout rules).

## 5. Layout headroom (P1)
- Design CTA buttons, tabs, nav to survive +30-40% text expansion (German, Finnish, formal Urdu registers)
- No fixed-width one-word controls; no text over image hotspots that shift with translation
- CJK: same info in fewer chars; do not pad layouts assuming CJK needs expansion
- Truncation rules: ellipsis end-of-line per direction (`text-overflow` respects dir), never mid-word clipping for Arabic connecting letters mid-string

## 6. Content & culture (P1)
- Locale-appropriate sample personas, names, imagery (i18n-aware examples in copywriting.md section 7)
- Color semantics shift by culture (white = mourning in some East Asian contexts; green religious resonance); sanity-check accent choices for the audience
- Icons do not always travel (mail envelope, hand gestures, check/x marks read differently)
